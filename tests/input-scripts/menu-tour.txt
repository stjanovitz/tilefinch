# Tilefinch scripted-input scenario 1: the chrome tour.
#
# Starts exactly where a normal PSP boot does: native HOME. It moves between
# both launch tiles, creates another native HOME tab through the real tab UI,
# then opens the local screenshots document to drive page-only controls before
# covering appearance settings, collections, and HOME return paths
# before leaving through the menu's own EXIT row. See
# docs/engineering/INPUT_SCRIPT_HARNESS.md for the format.
#
# Every step counts idle frames, not wall-clock frames: the stepper holds its
# position while a navigation, render job, or media surface is in flight, so
# the same file walks the same sequence under PPSSPP and on a PSP-3000.
#
# Order matters. Native HOME intentionally has no document to reload, scroll,
# bookmark, or read, so page-only work follows the screenshots document.
#
# The running comment tracks `menu_selection`, which persists across menu
# opens. Menu rows, in order:
#   0 address  1 home   2 tabs      3 library   4 bookmarks  5 history
#   6 reader   7 find   8 save      9 bookmark 10 screenshots
#  11 options 12 screenshot        13 exit
#
# Deliberately skipped, because each opens a text-entry modal or reaches the
# network: 0 address, 7 find, 8 save, 12 screenshot. Those belong to a second
# script that owns the on-screen keyboard. TRIANGLE is skipped too: the
# reader-mode long-press measures milliseconds rather than frames.

wait 30
mark boot

# --- Native HOME, then another HOME tab through the shipping UI -----------
tap down
wait 4
tap right
wait 4
mark home-first
# menu_selection 0 -> 2 (Tabs), then the trailing row creates a HOME tab.
tap select
wait 4
press 2 down
tap cross
wait 8
mark tabs-first
tap down
tap cross
wait 12
mark home-tab

# Native HOME is the only built-in start surface. Open a different internal
# document for the page-only actions below: 2 -> 10 (Screenshots).
tap select
wait 4
press 8 down
tap cross
wait 20
mark page

wait 8

tap square
wait 40
mark reloaded
